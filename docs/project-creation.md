# Project creation

`new <dir> [--compiler microsoft|rust-experimental] [--no-git]` creates a project. `init` accepts the same options and uses the selected `--project` directory or current directory. These commands return the shared JSON version 1 and exit categories when `--json` is present.

The initial release pins `fleur.json` to Fleur 0.1.0 with format version 1, contract version 1 and the Microsoft compiler. The generated package metadata records the same Fleur version. Its real Bun lock pins Preact 11.0.1, TypeScript 7.0.2, Bun types 1.4.3, oxlint 1.87.0, Vite 8.3.4 and Tailwind 4.3.3 with its matching Vite plugin. The lock does not pretend that an unpublished Fleur package exists in the registry. The experimental Rust compiler returns `PREREQUISITE_UNAVAILABLE`, exit 4, until its equivalence gate passes. It never falls back silently.

Creation supplies client, server, shared, assets, tests, migrations and seeds directories and project-local TDD guidance. This slice does not supply working application APIs, a running application or lifecycle/verification commands. No dependency installation or prerequisite setup occurs during creation.

Existing README, LICENSE, hidden files and user instructions are preserved. Runtime files are ignored by an owned `.fleur/.gitignore`; existing root ignore rules are not edited. Application directories, manifests, locks or an existing Fleur skill collide before writes and return `PROJECT_COLLISION`, exit 5. AGENTS.md and CLAUDE.md receive a marked versioned section after user content. Existing generated markers require resolution and block creation; repeated initialization never appends a second section. Existing instruction symlinks and symlink directory ancestors are rejected. Use a canonical path if the operating system provides a symlink alias.

Git initialization is enabled by default, uses an empty template and makes no commit. Existing repositories, including ancestor repositories represented by a `.git` file, are reused. `--no-git` prevents initialization. Git output is not forwarded and execution is bounded by the remaining command timeout. The same absolute timeout is checked before filesystem mutations, including `--no-git` creation.

On a handled failure, creation removes its recorded files and empty directories and restores modified guidance only when its identity and generated contents still match. New files are also removed only when their exact generated bytes still match; concurrent user edits remain for inspection. Guidance is appended without rewriting existing bytes. Changed directory identities block unsafe restoration. Unexpected partial Git metadata is retained and reported as `RECOVERY_REQUIRED`, exit 5. No recursive deletion of user directories or Git metadata occurs. A recovery result identifies paths that need inspection.

Directory identity checks detect observed concurrent changes. Portable filesystem APIs do not make a sequence of directory checks and writes atomic against hostile parent renames; this implementation does not claim that stronger guarantee. Creation should run in a directory controlled by the invoking user.
