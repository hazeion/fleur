# Project creation

`new <dir> [--compiler microsoft|rust-experimental] [--no-git]` creates a project. `init` accepts the same options and uses the selected `--project` directory or current directory. An empty directory argument is invalid; explicit `.` and Unicode/space-containing names are accepted. These commands return the shared JSON version 1 and exit categories when `--json` is present.

The initial release pins `fleur.json` to Fleur 0.1.0 with format version 1, contract version 1 and the Microsoft compiler. The generated package metadata records the same Fleur version. Its real Bun lock pins Preact 11.0.1, TypeScript 7.0.2, Bun types 1.4.3, oxlint 1.87.0, Vite 8.3.4 and Tailwind 4.3.3 with its matching Vite plugin. The lock does not pretend that an unpublished Fleur package exists in the registry. The experimental Rust compiler returns `PREREQUISITE_UNAVAILABLE`, exit 4, until its equivalence gate passes. It never falls back silently.

Creation supplies client, server, shared, assets, tests, migrations and seeds directories, project-local TDD guidance and offline `docs/fleur.md`. Both instruction files name the approved imports and refer to the same offline pinned guidance. Versioned generated content derives from the packed release package metadata, including the project pin, package metadata and skill version. Generated `tsconfig.json`, `.oxlintrc.json` and a separate frozen `lint/` graph provide strict Microsoft TypeScript 7.0.2, oxlint 1.87.0 and ESLint 10.12.0 with typescript-eslint 8.71.2 and its independent TypeScript 6.0.3 analyzer. `shared/placeholder.ts` only exports an empty module so compiler and lint commands have a real input. After explicit frozen dependency installation, `bun run types` and `bun run lint` execute those tools. Add the first requirements-based test before `bun run test`; no fabricated passing test is generated.

This slice does not supply working application APIs, a running application or Fleur lifecycle/verification commands. No app build script or production artifact is generated. No dependency installation or prerequisite setup occurs during creation.

Existing README, LICENSE, hidden files and user instructions are preserved. Runtime files are ignored by an owned `.fleur/.gitignore`; existing root ignore rules are not edited. Application directories, manifests, locks, generated compiler/lint configs, lint directory, pinned offline documentation or an existing Fleur skill collide before writes and return `PROJECT_COLLISION`, exit 5. AGENTS.md and CLAUDE.md receive a marked versioned section after user content. The AGENTS.md section ends with a Database section for application agents: typed queries and mutations as the only data access path, why raw SQL and ORM imports are unavailable, the reviewed migration and declarative seed workflows, approval-only reset, credential and disposable-test-data rules, and the checks to run after a schema change. It names only database operations in the release command catalog and lists later ones, such as the schema overview, `status` database health, `fleur dev` initialization and the development-only `db query` diagnostic, as not available. CLAUDE.md references that section instead of duplicating it. Each later database slice updates the section in the same change. Regenerating guidance replaces exactly one marked section with the current release text and keeps every byte outside it; missing, duplicated or misordered markers fail instead of guessing. The explicit refresh command that uses it is a later slice. Existing generated markers require resolution and block creation; repeated initialization never appends a second section. Existing instruction symlinks and symlink directory ancestors are rejected. Use a canonical path if the operating system provides a symlink alias.

Git initialization is enabled by default, uses an empty template and makes no commit. Existing repositories, including ancestor repositories represented by a `.git` file, are reused. `--no-git` prevents initialization. Git output is not forwarded and execution is bounded by the remaining command timeout. The same absolute timeout is checked before filesystem mutations, including `--no-git` creation.

Before reporting success, creation rechecks the identities and exact expected contents of every generated file and modified guidance section. A changed pin or other observed concurrent edit blocks success and remains available for recovery.

On a handled failure, creation removes its recorded files and empty directories and restores modified guidance only when its identity and generated contents still match. New files are also removed only when their exact generated bytes still match; concurrent user edits remain for inspection. Guidance is appended without rewriting existing bytes. Changed directory identities block unsafe restoration. Unexpected partial Git metadata is retained and reported as `RECOVERY_REQUIRED`, exit 5. No recursive deletion of user directories or Git metadata occurs. A recovery result identifies paths that need inspection.

Directory identity checks detect observed concurrent changes. Portable filesystem APIs do not make a sequence of directory checks and writes atomic against hostile parent renames; this implementation does not claim that stronger guarantee. Creation should run in a directory controlled by the invoking user.


The repository's reproducible generated-toolchain check is `bun scripts/verify-generated-project.ts`. It packs the actual executable, decodes the owned gzip archive through that Bun runtime before absolute tar extraction, creates a disposable project with only Bun on PATH, installs both frozen graphs into an isolated cache, checks positive explicit .ts/.tsx and Preact fixtures with both compiler and lint engines, rejects intended invalid type/unused-binding fixtures, and bundles the real Preact fixture with Bun. It proves tooling setup, not application runtime or production-artifact behavior. The script removes its owned disposable fixture afterward.
